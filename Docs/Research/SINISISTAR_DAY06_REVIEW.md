# Day 6 착수 전 검토안 — 아직 구현하지 않음

후속 변경: 사용자가 즉시 가능한 기능 적용을 승인하여 [전투 기반과 Day 5 밸런스](../REFERENCE_APPLY.md)를 반영했다. 이 문서는 그 이전 검토안이며, 실제 도트 애니메이션 연결은 여전히 디자인 준비 대기다.

작성일: 2026-11-07 (Asia/Seoul). 사용자 최신 지시: 시니시스타 심층 분석 후 알리고, **6일차 시작 전에 먼저 묻는다**. 기존 디자인 준비 대기도 유지한다.

## 추천 범위

**승인된 캐릭터 디자인의 Idle / Run / Attack / Hit를 기존 전투 상태에 연결하고, 보이는 공격과 실제 판정이 일치하는지 검수한다.** 원본 도트·코드·음원을 가져오지 않는다. Day 7 역할 차별화, Day 8 카메라, Day 16~17 3D HUD를 한꺼번에 시작하지 않는다.

근거: [통합 분석](SINISISTAR_DEEP_ANALYSIS.md), [실제 프로젝트 대조표](SINISISTAR_PROJECT_MAPPING.md), [기존 디자인 인계](../DAY06_DESIGN_HANDOFF.md).

## 시작 전에 필요한 결정

| 항목 | 현재 상태 | 추천과 필요한 판단 |
| --- | --- | --- |
| 디자인 자료 | 최종 동작 시트 확인되지 않음 | 확정된 디자인·프레임 자료를 우선 확인. 준비되지 않았다면 실제 도트 연결은 대기 |
| 공격 선딜 | 입력 즉시 판정 | 준비 프레임이 있다면 판정 시점도 맞춘다. 기존 즉시형 유지/선딜 추가 중 실제 시트를 보고 선택 |
| 공격 방향 | 시작 방향 Hitbox 고정, 몸 방향 변경 가능 | Attack 동안 몸·무기·판정의 기준 방향을 통일하는 방식을 우선 검토 |
| 이동·점프·전환 | 공격/회복 중 허용 | 이번 애니메이션 연결만으로 무단 제한하지 않음. 필요하면 조작감 변경으로 별도 확인 |
| 시간 기준 | 전투 타이머, 히트스톱 존재 | 애니메이션과 판정의 권위 있는 시간축을 하나로 정함 |
| 공중 표시 | 점프 기능은 이미 존재 | 신규 Jump/Fall 제작을 자동 요구하지 않고 기존/제공 프레임 사용 규칙 합의 |
| 몬스터 디자인 | A/B 같은 표적 이미지 | A/B 각각의 디자인 준비 범위에 맞춰 연결. 새 외형 자동 생성 금지 |

사용자에게 한 번에 모든 세부 수치를 고르게 할 필요는 없다. 먼저 **착수 여부와 준비된 디자인 자료**를 확인하고, 실제 프레임을 본 뒤 게임 느낌이 바뀌는 선택만 구체적으로 제시한다.

## 아트 전달 체크리스트

| 자료 | 확인할 내용 |
| --- | --- |
| 파일 | 투명 PNG/스프라이트 시트, 동작명, 프레임 순서 |
| 몸체 | 48px 키 출발점 유지 여부, 인물별 동일한 몸체 비율 |
| 기준점 | 발바닥 기준선, 피벗, 기본 바라보는 방향 |
| 무기 | 사슬·장검·방패의 최대 여백, 뒤집기 시 정렬 |
| 시간 | 동작별 속도·반복 여부, 준비·타격·회수 구간 |
| 중단 | 피격·전환 시 어떤 표시로 즉시 전환할지 |

프레임 수와 FPS는 원작을 실측해 확정한 값이 아니다. 임의로 6프레임/12FPS 같은 값을 승인된 사양으로 기록하지 않는다. 기존 콘셉트 이미지와 GLB는 최종 동작 시트가 아니다.

## 승인 후 구현 순서 초안

1. 받은 자료의 몸체 크기·발 기준선·피벗·무기 여백 확인.
2. 기존 상태에서 Idle/Run/Attack/Hit로 가는 매핑 정의.
3. 공격 시작·명중 가능·종료·취소의 시간 관계 정리.
4. 상태와 Animator 연결. 같은 공격을 타이머와 이벤트가 중복 발동하지 않게 처리.
5. 피격·사망·전환·비활성·R 초기화의 표시와 판정 종료 확인.
6. 적 A/B 예고와 실제 타격 방향·범위 확인.
7. 기존 회귀 검사와 화면 검수, 완료/누락 기록.

## 합격 기준

- 무기가 닿는 동작과 실제 피해가 납득 가능한 시점에 일치한다.
- 한 공격/한 대상당 중복 피해 방지가 유지된다.
- 공격 중 반대 방향 입력에서도 표시와 판정의 방향 규칙이 일치한다.
- 피격·사망·전환 후 이전 공격이나 늦게 도착한 이벤트가 살아나지 않는다.
- 히트스톱에서 몸·무기·판정 시간이 함께 정지하고 복구된다.
- 이동·점프·전환과 HP/HUD가 기존대로 동작한다.
- A/B의 예고·발동·회복을 그림으로 구분할 수 있다.
- 제공되지 않은 동작과 미검수 사항을 완료로 보고하지 않는다.

## 변경하지 않은 것

이 문서는 분석과 검토용이다. 새 코드·씬·Animator·애니메이션·캐릭터 디자인을 만들지 않았다. 3D 모델의 리깅·임포트·HUD 연결 완료도 주장하지 않는다.
